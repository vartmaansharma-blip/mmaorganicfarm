# Dashboard review with sign-in paused

A server-only `FARM_DASHBOARD_REVIEW=true` enables a public, read-only dashboard on the dedicated preview branch. The mode is ignored when `VERCEL_ENV=production`. A URL, role cookie or browser setting cannot activate it. Remove the preview flag to restore the normal sign-in requirement; the authentication implementation remains intact.

The preview renders the actual farm pages and components. Its three perspectives are Owner/co-founder, Manager and Driver. A persistent label identifies sample data and paused changes. The role switch changes only the sample perspective and confers no real staff membership.

The bundled snapshot is generated by `scripts/generate-dashboard-review.mjs` entirely in a disposable local PostgreSQL database. Its sample customers, payments, physical intake and driver run are fictional. It contains no production exports or credentials. Sample dates shift with the review day to keep navigation useful.

The review Supabase client intercepts every read locally, using an explicitly non-routable host. Mutation calls, staff invitations and unlisted RPCs return a review-only error. The preview proxy also blocks public payment/API routes and redirects public/auth pages to the dashboard. No live database or provider call is used for the review. This is visual/navigation review, not evidence that a real operation or payment was completed.

The production application retains its existing authentication, staff checks and write paths. A real release of notifications and intake still requires the two reviewed migrations. The synthetic preview does not activate them or substitute for authenticated production verification.

For another AI agent: open the supplied preview at `/farm`, inspect every navigation section, open the notification bell, expand stacks, use all three review perspectives, and inspect desktop/mobile layouts. Report concrete issues by page, trigger and expected behaviour. Edits are intentionally paused in this preview.
